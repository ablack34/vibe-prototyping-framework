# Engagement Artifacts

This folder holds **shared, durable engagement artifacts** generated by the VIBE agents. **It IS committed to git** so every team member (TPM, designer, engineer) can see the same engagement state after a `git pull`.

## What Lives Here

After you run `/vibe-kickoff`, an `engagement/{{engagement-kebab}}/` subfolder is created. Agents write the following files to it:

| File | Generated By | Used By |
|------|-------------|---------|
| `discovery-summary.md` | `@VIBE Discover` | `@VIBE Disrupt`, `@VIBE Ideate`, `@VIBE Deliver` |
| `transcript-analysis.md` | `@VIBE Transcript Analyst` | `@VIBE Discover`, `@VIBE Disrupt` |
| `ideation-concepts.md` | `@VIBE Ideate` | The team reviews to pick a concept |
| `selected-concept.md` | `@VIBE Ideate` | `@VIBE Deliver`, engineer |
| `spark-prompts.md` | `@VIBE Ideate` | TPM/designer pastes into GitHub Spark / Copilot Studio |
| `engineering-brief.md` | `@VIBE Ideate` | **Engineer's primary input for Build** |
| `handoff-data.json` | `@VIBE Deliver` | Final deliverable to the customer |

## What Does NOT Live Here

- **`state.json`** lives in `.copilot-tracking/vibe/{{engagement-kebab}}/` (gitignored, per-user). Each team member regenerates their own view of phase progress from the committed artifacts.
- **`PROJECT-CONTEXT.md`, `requirements-summary.md`, `solution-design.md`, `CHECK-IN-NOTES.md`, `PROTOTYPE-LIMITATIONS.md`** live in `templates/` (committed). The kickoff fills them with your engagement's values.
- **Customer source materials** (decks, transcripts, questionnaire exports) live in `sources/` (committed).

## Why This Folder Exists

Without it, the TPM's discovery and ideation work was trapped on their machine — the engineer couldn't read the engineering brief without screen-sharing or zipping files. Committing these artifacts means the engineer just does `git pull` and reads [engineering-brief.md](engineering-brief.md).
