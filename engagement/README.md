# Engagement Artifacts

This folder holds **shared, durable engagement artifacts** generated by the VIBE agents. **It IS committed to git** so every team member (TPM, designer, engineer) can see the same engagement state after a `git pull`.

## What Lives Here

After you run `/vibe-kickoff`, an `engagement/{{engagement-kebab}}/` subfolder is created. Agents write the following files to it:

### Preparation (Week 0)

| File | Generated By | Used By |
|------|-------------|---------|
| `PROJECT-CONTEXT.md` | `/vibe-kickoff`, then refined by every later phase | Every VIBE agent — single source of truth |
| `engagement-brief.md` | `@VIBE Preparation` (S42-internal view) | The team |
| `customer-brief.md` | `/vibe-customer-brief` (customer's voice — draft) | `@VIBE Discover`, `@VIBE Disrupt` |

### Discover (Week 1)

| File | Generated By | Used By |
|------|-------------|---------|
| `discovery-summary.md` | `@VIBE Discover` | `@VIBE Disrupt`, `@VIBE Deliver` |
| `personas.md` | `/vibe-personas` (required deliverable) | `@VIBE Disrupt` |
| `problem-statement.md` | `/vibe-problem-statement` (required deliverable) | `@VIBE Disrupt` |
| `current-state-journey.md` | `/vibe-current-journey` (required deliverable) | `@VIBE Disrupt` |
| `transcript-analysis.md` | `@VIBE Transcript Analyst` | `@VIBE Discover`, `@VIBE Disrupt` |

### Disrupt (Week 2 — customer co-creation workshop)

| File | Generated By | Used By |
|------|-------------|---------|
| `workshop-agenda.md` | `/vibe-workshop-agenda` | Workshop facilitator |
| `workshop-record.md` | `/vibe-workshop-record` (post-workshop) | `@VIBE Disrupt`, the engineer |
| `selected-concept.md` | `/vibe-selected-concept` | `@VIBE Deliver`, the engineer |
| `future-state-journey.md` | `/vibe-future-journey` | The engineer |
| `storyboard.md` | `/vibe-storyboard` | **Engineer's primary input for Build** |
| `spark-prompts.md` | `/vibe-concepts` | TPM/designer pastes into GitHub Spark / Copilot Studio |
| `ideation-concepts.md` | `/vibe-concepts` | Used in the workshop as pre-vetted candidates |

### Design & Develop (Week 3)

| File | Generated By | Used By |
|------|-------------|---------|
| `engineering-brief.md` | The engineer — first Build task, written from `storyboard.md` + `selected-concept.md` + `future-state-journey.md` | The engineer (then `@VIBE Deliver` and `/vibe-prd`) |

### Deliver (Week 4)

| File | Generated By | Used By |
|------|-------------|---------|
| `handoff-data.json` | `@VIBE Deliver` | Final deliverable to the customer |
| `prd.md` (optional) | `/vibe-prd` | Customer / PMO / governance when a single combined PRD is required |

## What Does NOT Live Here

- **`state.json`** lives in `.copilot-tracking/vibe/{{engagement-kebab}}/` (gitignored, per-user). Each team member regenerates their own view of phase progress from the committed artifacts.
- **`solution-design.md`, `CHECK-IN-NOTES.md`, `PROTOTYPE-LIMITATIONS.md`** currently live in `templates/` as fill-in-place singletons. They may move to `engagement/{{engagement-kebab}}/` in a future PR to make the templates-as-pure-scaffolds invariant complete.
- **Customer source materials** (decks, transcripts, questionnaire exports) live in `sources/` (committed).
- **Blank scaffold templates** live in `templates/` and are **read-only** — agents and facilitators copy from `templates/` into `engagement/{{engagement-kebab}}/` and fill there. `git diff templates/` should always be empty.

## Why This Folder Exists

Without it, the TPM's discovery and ideation work was trapped on their machine — the engineer couldn't read the engineering brief without screen-sharing or zipping files. Committing these artifacts means the engineer just does `git pull` and reads [storyboard.md](storyboard.md) (the Disrupt contract) and then writes [engineering-brief.md](engineering-brief.md) as their first Build task.
